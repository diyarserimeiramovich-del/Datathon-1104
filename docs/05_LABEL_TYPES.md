# Разметка типов нарушений — инструкция на 20–30 минут

Зачем: в `open_labels.xlsx` есть только «нарушение / без нарушения», без типа. Из-за этого
`eval.evaluate` считает пропуском любое нарушение, включая те, которые правило в принципе
не моделирует (например, деньги на столе). Пока тип не проставлен, точность и полнота
отдельного правила неизмеримы.

## Что смотреть

`data/contacts/X-*.jpg` — контактный лист по каждой метке: 7 кадров от −3 до +3 с,
жёлтым подписан таймкод, кадр метки помечен `<= METKA`. Листы пересоздаются командой:

    python -m eval.contact_sheets data/labels_grouped.csv ../open/videos

## Что заполнять

`data/labels_types.csv` — колонки `video,timecode,type,comment`. В `type` вписать один
или несколько идентификаторов через `;`, в `comment` — что видно своими словами.

Допустимые идентификаторы (совпадают с `id` в `rules.json`):

| id | что должно быть на кадрах |
|---|---|
| `cashier_left_workplace` | кресло кассира пустое несколько секунд: человек стоит у сейфа, у двери или вышел |
| `cash_left_unsecured` | банкноты лежат на столе, клиента за столом нет, в помещении появился другой человек |
| `personal_device_in_cash_zone` | телефон в руках кассира или на столе |
| `unauthorized_person_on_cashier_side` | посторонний по ту же сторону стола, что и кассир |
| `cash_not_counted_with_client` | деньги переданы или приняты без пересчёта на машинке в присутствии клиента |
| `other` | нарушение есть, но не подходит ни под один тип — опишите в `comment` |
| `unclear` | по кадрам не понять, нужен просмотр видео целиком |

Правила заполнения:

- Если на видео два события (X-4 и X-47, метки 57 и 68 с) — две строки, тип у каждой свой; дубликаты X-47 = X-4 и X-48 = X-5 можно заполнить один раз и скопировать.
- Если сомневаетесь — `unclear` лучше, чем угадывание: такие видео пойдут в отдельный список на ручной разбор, а не в метрику.
- Часть «нарушений» может оказаться спорной или вовсе без нарушения — тогда поставьте `unclear` и напишите, что видно.

## Что будет после заполнения

1. `eval.evaluate` начнёт считать метрики по типам: precision/recall для каждого правила на своей подвыборке, а не «поймал ли что-нибудь».
2. Порог `cashier_away` пересчитается только на видео типа `cashier_left_workplace` — сейчас в знаменатель попадают 19 нарушений других типов, из-за чего полнота 0.14 выглядит хуже, чем есть.
3. Появится список типов, под которые правил нет, — это план следующих предикатов (пересчёт денег, передача наличных).
