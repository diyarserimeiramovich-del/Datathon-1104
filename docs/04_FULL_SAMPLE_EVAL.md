- Видео: все 42 файла из `../open/videos` (40 уникальных: X-47 = X-4, X-48 = X-5 по md5), 1433 с суммарно, 2901 кадр.

- Время: ~2 ч на GPU (X-47 длиной 142 с — около 7 мин, то есть **длинные видео выходят за бюджет 5 мин на видео**; короткие — 1.5–3 мин).

## Выбранная рабочая точка

`gte = 0.44`, `min_duration_sec = 2.0`: **TP=3, FP=0, TN=20, FN=19**, средняя ошибка таймкода 6.7 с (5.0–8.1 с).

Решение принято по правилу проекта «ложное обвинение кассира дороже пропуска»: 0.44 — минимальный порог с нулём ложных срабатываний, запас до ближайшего негатива всего 0.01 (X-25 и X-31 — 0.43). Leave-one-out по 42 видео выбирает **тот же 0.44 во всех 42 фолдах** и даёт те же TP=3 / FP=0, то есть выбор не случаен, но и не щедр.

## Второе правило

`cash_left_unsecured` не сработало ни на одном из 42 видео. Оно не ломает метрику, но и пользы не приносит: деньги нигде не превышают 0.6 одновременно с отсутствием клиента.

## Чем это лечится

Порогом — ничем. Правило ловит 3 из 21 нарушения, потому что 2B-модель на 320 визуальных токенах не различает «кресло пустое» и «кресло занято, но человек наклонился». Варианты по возрастанию цены:

1. Отдельный детектор человека (YOLO/RT-DETR) и геометрия кресла кассира — детерминированный признак занятости, без VLM.
2. Модель крупнее (Qwen2-VL-7B / InternVL2-8B) и/или больше визуальных токенов (MAX_TOKENS 640–1280): кэш пересчитать, порог подобрать тем же `eval/sweep.py`.
3. Другой предикат: «видно ли кассира за столом» (позитив) вместо «отсутствует ли» — отрицания VLM путают чаще.
4. Пока правило остаётся только пометкой для ручного просмотра, не автоматическим обвинением.
